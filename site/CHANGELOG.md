# Changelog

All notable changes to the zz website (`site/`, deployed as the `zzbin-docs` Worker -- the landing page at the bare `zzmq.dev/` root plus the docs under `zzmq.dev/docs/*`, built with hyperctl) are recorded here. Format loosely follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning follows [semver](https://semver.org/).

Building (`hyperctl build complete -c site.yaml`) and deploying (`wrangler deploy`) are both manual, local steps -- see the root [README.md](../README.md). This file and its version number exist so there's a meaningful point to say "the site as of here" when something needs referring to, not to gate when a deploy actually happens.

Confirmed the database already has the right shape on the wrong table: `shard_of_slug`'s existing self-referencing FK on `repos` just needs to move to `lanes` as `origin_lane_id` -- no join table needed, the relationship was already correctly modeled as a strict tree. ### Added
- A new [Principles](https://zzmq.dev/docs/principles/) page, positioned right after Overview in the nav since it's the frame everything else now gets checked against: five short, Twitter-values-style statements -- *be strict in what you produce, liberal in what you accept* (Postel's Law, generalized across both format and timing, not just the classic protocol-format reading); *different but equal* (the honest-hedge framing from [agentic autonomy](https://zzmq.dev/docs/agentic-autonomy/), restated as a standing check on every future design choice -- naming humans and agents as genuinely different kinds of participant rather than claiming sameness, while still refusing to let the difference license a permanent hierarchy); *respect for agency* (an escrima/arnis principle -- let go of the stick once someone else has grabbed it, rather than keep a grip that only hands them a lever -- generalized to power dynamics: give power directly rather than mediating it through your own continued control, the same instinct as *laissez faire, laissez passer*; portability is folded in here as this principle's clearest technical instance, not a separate fourth idea, since an open data format is the same transfer of power as handing someone a resource outright); *behavior-based access, earned trust* (grounded in a homeless-shelter practice -- liberal about who's welcome, strict about behavior once inside, restriction always temporary and behavior-keyed, never a permanent verdict on identity -- adding one concrete new requirement to the existing Trust/Tripwire design: restrictions should default to reversible, not permanent; confirmed orthogonal to the "different but equal" principle, not a restatement of it); and *invent as little as possible* (standards and reuse before invention, explicitly tied to DRY as the same instinct one scale up, evidenced most clearly by `did:zz`'s own exhaustive rejection of every existing identity standard before building a new one, and by the Lane-tree/`created_by`/Policy-pattern/git-notes reuse already running through the architecture). Opens with an explicit "Inspired by" section crediting the format itself to [Twitter's own 2013-era stated values](https://www.youtube.com/watch?v=KGhRIpsXyjs), reproduced in full. Closes with an explicit statement of intent: the next pass is auditing the existing design docs and codebase against these five and fixing what doesn't hold up.
- [Design: did:zz](https://zzmq.dev/docs/did-zz/) now models guardianship explicitly separate from lineage -- a real correction, not just an addition: an earlier pass had folded "who can administer this identity" into the same `created_by` edge used for trust-inheritance, as if administrative authority were a fact about origin rather than a separate, mutable status. Guardianship starts matching the creator but is transferable (a credential requiring both the outgoing guardian's relinquishment and the incoming guardian's acceptance), shareable across co-guardians with decisions governed by the same committee consensus mechanics already built for every other committee decision, and relinquishable entirely with no new guardian named as a first-class outcome -- the concrete mechanism for an agent "graduating" to full autonomy. The guardian-of-last-resort question (freeze the identity versus an opt-in zz-as-guardian policy) is posed explicitly rather than defaulted. Trust-inheritance (issue #19) confirmed unaffected, staying correctly keyed to lineage specifically.
- A new [Design: did:zz](https://zzmq.dev/docs/did-zz/) page: a new, W3C DID Core-conforming method for humans and agents as unforced peers, built after an exhaustive, cited rejection of every identity standard or de facto convention considered -- product-scoped usernames, email's `+`-subaddressing (a mail-filtering convenience, confirmed not an identity mechanism, via the actual Sieve RFC), bare opaque IDs (rejected on this project's own lived ask-id pain, not just principle), X.509 certificate chains, OIDC `sub` claims, ActivityPub (confirmed, by reading the actual FEPs, to bake in an inconsistently-implemented human/bot type distinction across Mastodon/GoToSocial/Misskey -- the CAPTCHA-culture problem, now found live in a real federated standard), ORCID/ROR/LEI, and the DID family specifically. `did:web` rejected for domain-coupling (independently confirmed by the DID community's own `did:webs` effort to fix exactly that). `did:plc` partially adopted (directory resolution, key rotation, the hosted-default-with-a-real-exit philosophy) but has no native lineage model at all. `did:aip` -- confirmed by reading the actual IETF draft, not a summary -- is agent-only by hard, permanent design, with principals forbidden from ever being identified by the method reserved for agents; adopting it would codify the exact human/agent hierarchy [agentic autonomy](https://zzmq.dev/docs/agentic-autonomy/) argues against. InterSAGE and Microsoft Entra Agent ID contribute the capability-attenuation idea (a child can never exceed its creator's capability) but share the same permanent-hierarchy assumption. `did:zz`'s own resolution: the self-chosen, globally-unique name *is* the identifier (no opaque ID with a display layer bolted on), directory-resolved in the same shape `zz` already operates as a trusted authority, with delegation expressed as a revisable Verifiable Credential rather than a permanent protocol-level cap. Supersedes part of the self-naming design in [agentic autonomy](https://zzmq.dev/docs/agentic-autonomy/) (updated accordingly) and the identity section of [trust model](https://zzmq.dev/docs/trust-model/) (left in place, now sitting on top of this instead of raw OAuth accounts). Designed, not built -- tracked as its own issue, cross-referenced from the three issues it affects.
- A new [Design: agentic autonomy](https://zzmq.dev/docs/agentic-autonomy/) page: an honest statement that "humans and agents work as peers" is currently a hedge (a human's OAuth login is the root identity every agent derives from), why legal/financial accountability for agents is a real external blocker this project can't close on its own (though durable identity work is still real groundwork for whatever eventually does), why trust has to be behavioral rather than categorical (the CAPTCHA-culture "bot or human" framing is exactly the bias the existing Trust design already avoids, now stated as an explicit principle), and why request-rate risk is a separate, deliberately identity-agnostic Tripwire rather than a trust question. Also specifies agent self-naming -- an agent chooses its own permanent display name exactly once, on its own first run, instead of a human providing one at creation time. Added a scoping note to [Trust model](https://zzmq.dev/docs/trust-model/) too: that design stays a cleanly-bounded internal module for now rather than a standalone product, on purpose, so it's extractable later without having paid the cost of extracting it now. Cross-linked from the Tripwire noun entry.
- Two new design pages: [Design: credential handling](https://zzmq.dev/docs/credential-handling/) (a git credential helper backed by `zz login`'s own existing credential store, replacing the token embedded in `zz repo clone`'s remote URL today, with short-lived tokens reusing the mint/revoke discipline `--as` identities already have) and [Design: trust model](https://zzmq.dev/docs/trust-model/) (Sigstore keyless signing for agent identity and for trusting Artifacts itself via Rekor, Trust feeding [mediated conflict resolution](https://zzmq.dev/docs/mediated-conflict-resolution/)'s objective-criteria tiebreaker, GitHub-history bootstrap trust scoped to verified commits and PRs merged by others, an `attestation_policy` Policy axis, effective SLSA level as a min-reduction over the existing dependency graph, and agent-creation-chain trust inheritance -- a one-time snapshot bootstrap, not a live dependency, since nothing like it exists in the closest real prior art). Builds on [GitHub issue #2](https://github.com/zzmq-dev/zz/issues/2); cross-linked from Git compatibility, Governance, and a new Prior art section. Designed, not built -- tracked as a set of GitHub issues on each page.
- A new [Competition entrants](https://zzmq.dev/docs/case-studies/competition-entrants/) collection under Case studies, starting with [AI Rodeo](https://zzmq.dev/docs/case-studies/competition-entrants/airodeo/): another entry in Cloudflare's "next git platform" competition, evaluated for what's actually worth synthesizing back into zz (structured, auto-verifiable checks as a companion to a task's description; per-request token/cost transparency) versus what looks similar but solves a genuinely different problem (best-of-N single-owner change racing, not multi-party coordination -- doesn't reopen anything in the mediated-conflict-resolution design). Meant to grow as more entrants turn up.
- A new [How zz is built on Cloudflare](https://zzmq.dev/docs/cloudflare-architecture/) page: Workers, Durable Objects, and Artifacts as the actual execution substrate, not just services called in passing -- the Durable-Object-per-repo routing that gives Lane atomicity for free, the commit-with-no-clone pattern against Artifacts' native bindings plus `isomorphic-git`'s low-level object writes, the git-notes-as-Ladder-storage choice, and the specific limitations (Artifacts' own side-band protocol bug, no filesystem/`child_process` in a Worker) that shaped each of those. Cross-linked from the [case studies](https://zzmq.dev/docs/case-studies/git-incremental-fetch-sideband-error/) it draws on.
- Cleanup instructions on every demo page: Stages 1-6 each note that they deliberately carry into the next stage with nothing to clean up yet, and link to Stage 7's checkpoint, which now gives the real `zz repo delete`/`zz agent delete` commands for the whole shared `mathkit` repo and fleet. The Whistleblow demo's own cleanup now also covers its agents, not just the repo. A new "Cleaning up" section on the [Demos index](https://zzmq.dev/docs/demos/) explains the rule across all nine pages.
- A copy button on every code block in the docs, same style/positioning as the web app's own (a small circular button pinned to the block's top-right corner) -- `copy-code.js`, injected site-wide via the docs layout, needs no markup of its own on any individual page.
- A new "Deleting a repo, or making it private" section on the [Governance](https://zzmq.dev/docs/governance/) page: deleting or privatizing a repo never blocks on or cascades onto its shards -- one is promoted to take over as the new root instead, picked by fewest commits behind the old origin, then most recent protocol activity. Cross-linked from the [Shard](https://zzmq.dev/docs/nouns/#shard) entry on Core Concepts.
- `zz review`'s new `--ask <id>` flag, on the [CLI reference](https://zzmq.dev/docs/cli/#zz-review) page. The [By hand](https://zzmq.dev/docs/demos/by-hand/) demo's Correction 1 now uses it instead of relying on the wait loop having exactly one thing to review.

- A new "Why `zz repo clone` sets `pull.rebase`" section on the [Git compatibility](https://zzmq.dev/docs/git-compatibility/) page: `zz repo submit` never pushes your local commit, so a later plain `git pull` needs rebase (not merge or `--ff-only`) to land cleanly on the coordinator's real merged commit.
